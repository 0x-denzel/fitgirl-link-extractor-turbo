# Historical audit and implementation plan

This records the pre-implementation investigation. Implementation was subsequently approved. See [current release validation](../VALIDATION.md) for the final support policy, including removal of DataNodes landing-page extraction.

FitGirl Turbo Link Extractor — audit findings and proposed implementation

Audit date: 20 October 2026. Phase 1 is complete; Phase 3 is awaiting approval. The four Desktop release files are unchanged. Only audit scripts, fixtures, results, this report, and a read-only source checkout were created inside `audit_scratch`.

The source checkout is `audit_scratch/upstream`, from https://github.com/EditByDenzel/fitgirl-link-generator-updated at commit `27081e3`. Its four release files match the Desktop files after line-ending normalization. The repository also contains `app.py`, `download_util.py`, `extract_ff_links.py`, `.gitignore`, and `LICENSE`; these were reviewed. No repository AGENTS.md or existing tests were found. The Desktop distribution omits LICENSE.

Python 3.11; Playwright 1.63.0; playwright-stealth 2.0.3; BeautifulSoup 4.14.3; requests 2.32.5; installed Chrome 155.0.8059.80. Every browser launch used `headless=True`. Temporary browser profiles stayed in the scratch temp directory, which was empty after completion. Clipboard, Explorer, download-manager launches, and Downloads-directory output were mocked in regression checks.

**Measured results and their limits.** The live sample was the first archive part from the God of War III Remastered repack page linked in the existing README. The DataNodes public file ID was `ecjv21tb1weu`. Each of the three mirror pastes contained 21 links. Only landing pages, verification flows, and generated URL candidates were tested; CDN payload requests were aborted, so these results do not establish file integrity, CDN throughput, or completed downloads.

These are small, deliberately bounded experiments on one file and one network location, not population reliability estimates. The live harness sets a 12-second default action timeout and limits resolver retries to one; production uses longer defaults and multiple attempts. It also blocks payload downloads and installs routing in both A/B conditions. This changes navigation behavior and disables the ordinary HTTP cache. Thus F-Fast's 3/4 return failures are observed probe results, not a claim of a 75% field failure rate. A separate deterministic test reproduces the result-loss bug without network interception.

FileKeeper mean observed CDP bytes fell from 756,979 to 635,498 with images/fonts/media blocked: **16.0% less observed page traffic**. Mean elapsed time fell from 2.884 to 2.525 seconds: **12.4% in this sample**, with substantial run-to-run variability. F-Fast's return-path failure confounds speed comparisons, so no speed improvement is claimed there. CDP byte totals are page-session observations, not full browser/process network accounting.

**DataNodes network findings.** The public landing URL redirected to `/download`. Step 1 published a POST form with `op=download1`, `usr_login`, `id`, `fname`, `referer`, and `method_free`. No `token` field was present in the observed Step 1 form. Plain requests with the published fields and an ephemeral cookie session did not advance. The current engine's DOM-submit behavior did reach Step 2. The resulting DOM had a Turnstile widget, no populated `cf-turnstile-response`, no final download anchor, and no matching download button. HTTP 200 therefore did not mean successful resolution.

Cookies included `file_code`, `affiliate`, `lang`, and `cf_clearance`; only names were retained. Even after clearance was issued, neither the original resolver nor the current-Chrome session-reuse trials obtained the Step 2 token. Scripts, XHR/fetch, and challenge resources were kept enabled during resource-blocking trials. Normal headless identity, existing stealth settings, and ephemeral cookie reuse did not produce a successful extraction in the tested configurations. CDP was used for network measurement; Python Playwright exposes `context.new_cdp_session(page)`, not `page.driver`.

There is no evidence here for a fast or guaranteed DataNodes solution, but these tests also do not prove that headless extraction is fundamentally impossible. Arbitrary token strings, header changes, or reusing an already-consumed token cannot be treated as verified solutions. Cloudflare documents server-side validation, five-minute token validity, and single-use tokens: https://developers.cloudflare.com/turnstile/get-started/server-side-validation/ . Cookie presence is not proof of successful Turnstile validation.

Recommendation: retain DataNodes direct-URL passthrough and a bounded, best-effort resolver, remove the fixed ~6-second reliability implication, and prefer FileKeeper for automatic repack resolution. When DataNodes reports verification required, use a verified matching FileKeeper mirror, then repaired F-Fast. If the user supplied only a standalone DataNodes URL or paste, there may be no trustworthy alternative manifest; report that limitation instead of guessing a mirror. Do not introduce a visible-browser fallback.

Existing strengths: all inspected browser launches are headless. Each host resolver removes its own listeners in a finally block; 300 mocked removed-file resolutions left zero attached listeners. That test does not establish whole-browser memory stability for 100 live successful downloads. The baseline `python -x Download_FitGirl_Links.bat --help` passes with dependencies installed.

Auxiliary files have divergent behavior: `app.py` performs a synchronous requests call with no timeout; `download_util.py` emits per-file INFO logs; `extract_ff_links.py` has a separate engine and multiline progress. The macOS launcher can select that older engine if the BAT is absent. The `.command` file has LF endings but is tracked as mode 100644, so downloaded execution permissions need explicit packaging/documentation. README claims about native AES decryption, automated token handling, constant speeds, and zero setup exceed what this implementation establishes. Decryption is delegated to the PrivateBin web client.

**Proposed architecture, retaining the standalone BAT.** Keep line 1 byte-for-byte identical. Organize the Python body into small typed helpers and records inside the same file: source parsing, mirror manifests, filtering, browser session management, per-hoster resolution, progress rendering, and result persistence. Auxiliary entrypoints should delegate to that engine while translating their old CLI options, preventing divergent resolvers without making auxiliary files required for standalone use.

1. Parse URLs once with `urlsplit`, exact host/subdomain rules, HTML entity handling, stable source order, and identity deduplication. Preserve signed query strings and encoded paths exactly; decode only labels for filtering and filenames. Normalize Unicode filenames, remove controls/path separators, handle Windows reserved names, and bound length. Validate file input encoding and distinguish URLs, magnets, local files, repack pages, and paste URLs with missing keys.
2. Build a complete ordered manifest for each mirror rather than storing only one link per host. Carry the repack title and alternate manifests into the pipeline. Match alternatives by normalized archive filename, part number, language/optional category, and size where available. Require compatible manifests before switching; never combine incompatible archive sets. Preserve successful results and replace only verified matching unresolved entries. Open a per-host circuit breaker after verification failure to avoid repeating a full DataNodes timeout for every part.
3. Apply filters before both direct passthrough and browser work. Propagate CLI options through the selector. Keep interactive selection when appropriate; avoid new prompts in explicitly configured CLI runs. Return useful status for EOF, empty batches, all-filtered batches, unreadable files, and no available mirrors.
4. Use one managed headless browser with an ephemeral context per host and a fresh page per resolution. Track and await popup/download cleanup tasks. Close pages/contexts/browser in bounded finally blocks. Scope listeners to the active attempt. Capture validated redirect/header candidates before navigation, cancel any started archive download immediately, and stop waiting once a URL is found. F-Fast's second click becomes conditional on still needing a result. Classify success, removed, rate-limited, verification-required, transient failure, and cancellation explicitly.
5. Block images/fonts/media with host-specific exceptions; leave verification scripts, XHR/fetch, and CSS available. Prefer DOM predicates, response events, and per-attempt deadlines over fixed sleeps and networkidle. Use retry/backoff only for transient or rate-limit failures. Start sequentially within each host; concurrency is not needed to repair the measured failures and must not undermine host limits or ordered output.
6. Give one renderer sole ownership of the progress row. Use carriage return plus clear-to-end, terminal-width budgeting, control-character sanitization, and Unicode display-width handling. Show completed count, percentage, bounded bar, truncated title, and status; suppress per-link logging and child-process chatter. Finish the row once before the final summary. Use a concise final status when stdout is redirected.
7. Create the result sink before resolution and checkpoint each accepted URL before the next await. Flush durably, finalize atomically, and preserve successes on cancellation and unexpected failures. Perform bounded cleanup and clipboard/reveal handoff without a download-manager prompt after cancellation. Clipboard failure must not prevent file preservation or reveal. Resolve output paths absolutely; respect an explicit --output and keep the default Downloads behavior. Tests use scratch destinations and mocked integrations.
8. Use native CF_UNICODETEXT writing/reading on Windows with typed ctypes declarations, bounded retries, and correct allocation ownership; bounded UTF-8 pbcopy/pbpaste on macOS; wl-copy/wl-paste then xclip/xsel where available on Linux. Use argument-list OS launches and safe magnet handoff. Check .torrent basename, extension, size, and bencoded content before accepting it.
9. Parse --help before installing anything. Add a clear Python version guard, compatible dependency checks, bounded quiet installation, and a verified Chromium bootstrap when local Chrome is absent. Keep runtime assets local to the distribution where feasible and handle unwritable installs with a clear setup error. No Git or virtual environment is required. Preserve line 1, documenting that its generic nonzero-exit message cannot be fully corrected without a separate approved first-line change.

Playwright references supporting the implementation choices: https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route (routing, service workers, cache caveat), https://playwright.dev/python/docs/api/class-browsercontext#browser-context-new-cdp-session (CDP), and https://playwright.dev/python/docs/browsers (browser installation).

**Acceptance checks after implementation.** Preserve the exact first line and compile the Python body. Run --help both with the normal environment and a fixture simulating absent optional dependencies, confirming that help performs no installation. Require all regression expectations to pass. Exercise cancellation before resolution, after one result, during a retry, during cleanup, and during output/clipboard failure. Run 100-part local browser fixtures to assert bounded pages, listeners, tasks, and ordered output; report memory observations without treating them as a universal leak proof. Verify progress output at 40/80/120 columns, long Unicode names, and redirected stdout. Repeat bounded live mirror probes and validate fallback manifest matching. Windows integration can be exercised locally with controlled data; actual macOS/Linux clipboard and Finder behavior require those OS environments and will remain explicitly distinguished from mocked adapter checks.
